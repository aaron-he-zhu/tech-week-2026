# Contributing

English is the default interface and documentation language. Keep the Chinese interface and both READMEs in sync when behavior changes.

## Development

Use Node.js 24 and Python 3.13. From the repository root:

```sh
cd website
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements-dev.txt
npm ci
npm run verify
npm run preview:wishlist
```

On Windows, activate the virtual environment with `.venv\Scripts\Activate.ps1` in PowerShell. The preview listens only on `127.0.0.1:4173`; its SQLite database is in `.local/` and is separate from production. No Cloudflare or Google account is needed for ordinary local development. Google sign-in is optional and needs your own OAuth configuration.

## Changes and checks

- Run `npm run format` after editing and `npm run verify` before submitting. Verification includes formatting, JavaScript/Python lint, two reproducible builds, calendar and bilingual checks, API tests, localization tests and Python rendering tests.
- Keep SQL parameterized and visitor content rendered as text. Never put credentials, personal recovery links, D1 exports or real user records in a patch or fixture.
- Preserve anonymous identity, Google account merging, read-only sharing and contribution ownership. Add focused regression tests for changed behavior.
- Keep event IDs, taxonomy evidence, counts and chronology aligned across languages. A new editorial message needs an English entry in `website/src/locales/en.json`; missing translations stop the build.
- Put page structure in `website/templates/`. Templates autoescape ordinary data. Use `Markup` only for HTML generated by trusted rendering helpers, never raw event or visitor text.
- Do not edit `dist/` or `backend/event-ids.mjs`; they are generated. Default builds use fictional examples, without querying a calendar, Luma or an AI service. Keep real organizer snapshots and visitor data outside the public repository. See [content format](docs/content.md).

Use a feature branch and a pull request. Describe the user-visible behavior, why the change is needed and which checks passed. Pull requests run validation only; deployment is restricted to enabled `main` runs. The workflow does not execute schema migrations or production write tests.

See [architecture](docs/architecture.md), [deployment](docs/deployment.md), [security reporting](SECURITY.md) and [source notices](NOTICE.md). Contributions of original code are under the project's MIT license. Do not submit third-party material without permission to redistribute it.
